# 2026 前哨站

在目标下拉框选择“前哨站（2026）”，或启动：

```bash
./run.sh -- --config=res://configs/outpost_2026.cfg --remote
```

仓库默认仍为蓝色步兵3号，前哨站、车辆与符互斥。切换类别时停止旧指令、结算在飞弹丸、更新会话并将云台对准新目标；保留累计统计与相机内参。车辆参数在前哨站期间不参与运动，切回车辆恢复原设置。

规则图4-34（印刷第59页）给出三块中部装甲及顶部飞镖检测模块的布局；图5-16/17（第97-99页）给出专用装甲、有效检测区域与标识；表5-1/2和第5.5.1节给出受击与运动机制。制作规范第2.4.6.2节将飞镖视觉特征的具体尺寸指回比赛规则。

- 三块中部装甲相隔120度，按图中1114、1216、1318mm的高度层安装；仿真索引0/1/2对应1114/1318/1216mm，依次绕旋转轴正向排列。上述高度从前哨站底面计算，世界高度另加配置的底座高度。中部板面按75度对地安装，即内倾15度。
- 图示Phi550圆在仿真中用作装甲中心轨道圆，半径0.275m。底板宽0.650m，主体总高1.578m；默认底座0.30m，整体高度1.878m。
- 有效受击轮廓按图5-16构造：111mm参考宽度、2mm内缩、两侧5mm凹入、58mm中间段及16mm上下段，保留边缘过渡，不沿用车辆135x125mm的矩形受击近似。中心10x10mm方形为暴击区。

官方未给完整CAD及全部尺寸，因此塔身截面、厚度、固定件和装甲外壳为简化模型。外壳144x128mm、灯条中心距约130mm等未标注量按图示比例复原，不能称为官方精确尺寸。渲染塔身与物理遮挡使用同一组实体；装甲外壳与有效受击区域分别处理。局部光晕没有实体碰撞，也不扩大受击区；没有全图模糊。

## 独立配置

```ini
[appearance]
robot="outpost_2026"
team="blue"

[outpost]
forward=4.00
lateral=0.00
base_height=0.30
opponent_base_open=false
```

| 项目 | 缺省值 | 约束 |
|---|---|---|
| `forward` | 4.00 | [1,20]m，相对初始相机的前后距离 |
| `lateral` | 0.00 | [-15,15]m，向左为正 |
| `base_height` | 0.30 | [0,2]m，前哨站底面离世界地面的高度 |
| `opponent_base_open` | false | 布尔；训练中模拟“对方基地护甲展开”事件，触发不可撤销的本轮停转 |

这些字段均可省略，继承代码默认值，数值控件按两位小数编辑。固定几何与标定保留必要精度。相机/云台设置仍由正常的camera/gimbal节配置，修改FOV或标定仍须同步接入端description并重启视觉。前哨站不采用车辆的平移、往返、角速度、装甲伸展或400mm下沿限制，也不开放修改规则伤害和几何尺寸的界面。

## 运动、停转和重建

选择前哨站后开始本轮计时，重置本轮后从零重新计时。与累计统计所用的仿真时间分开，暂停时两者都冻结。初始相位为PI，每轮随机选择一个转向；切换红蓝目标不改变当轮转向、起始时刻和停转记录。

规则要求5秒内达到0.8pi rad/s，随后匀速，未指定电机加速曲线。仿真采用5秒线性加速并解析积分相位；转速在运行中不受车辆omega控制。以下任一条件触发停转：首次被击毁、前哨站本轮经过180秒、对方基地护甲展开。该事件保持锁定，清除界面复选框、重建和普通参数编辑都不能恢复旋转。

规则注明停转归至初始布局但未给出控制曲线。仿真保持原加速/匀速轨迹到下一次初始布局后停止，不另模拟电机减速。匀速时最多继续一圈，启动期间最多继续到5秒；不会以启动瞬间的微小速度长时间缓慢归位。自然180秒限制正好到初始相位。

击毁后灯条、光晕、塔身血条和顶部绿色引导灯熄灭。界面“模拟重建”在被击毁且本轮未达300秒时恢复750/1500HP和灯效，不重置旋转状态、统计或本轮时间，不能对存活目标重复重建。重新开始使用正常R重置本轮。

这里是单目标自瞄靶场，没有基地经济、RFID或完整赛程：重建按钮是训练事件，未实现比赛中基地每损失1000血量获得机会，以及工程5秒/其他机器人10秒占点的前置条件。`opponent_base_open`同样是显式训练事件，不表示场景中已存在对方基地。

## 17mm受击与物理遮挡

沿用现有17mm弹丸的出膛与重力抛物线，只对前哨站执行专用判定：

1. 弹丸与塔身、底座、装甲外壳/边框碰撞时被挡住，只计物理接触，不扣装甲血量；不会穿过塔身击中后面的装甲。
2. 正面进入有效区域，才检查接触时相对装甲的法向速度，必须严格大于12m/s。速度计算包含旋转装甲的运动，不用出膛速率直接替代。
3. 每块装甲分别保留50ms最小检测间隔。一次物理子步内多个弹丸按实际接触时间结算，避免先到的合法命中被后到的命中挤掉。
4. 初始血量1500，普通有效命中20HP，中心10x10mm方形内30HP，伤害最多扣剩余血量。击毁后实体仍能阻挡弹丸，但不会重复增加有效命中或击毁数。

原车辆受击行为保持原样，不把前哨站的新速度门限、受击多边形、阻挡或冷却强加给旧车型。顶部飞镖模块保留外观与非计分实体，本轮没有42mm或飞镖发射/红外识别链路，17mm击中它不扣血。

## 接入和验证

`appearance.robot="outpost_2026"`采用正常自瞄mode=1；`truth.armors`按实际三块板输出，状态增加可选`outpost`诊断对象。车辆和符仍分别输出四块/零块装甲，mode与此前一致。正式视觉只读取正常像素、云台反馈和控制协议，不使用这些真值角点；没有修改自瞄、runtime或fake_robot来识别新目标。

```bash
./run.sh --headless --script tests/outpost_tests.gd
./run.sh --audio-driver Dummy --script tests/outpost_ui.gd
python3 tests/outpost_integration.py --godot /absolute/path/to/godot
```

专用检查覆盖加速/积分、早期停转与归位、各装甲速度/间隔/暴击判定、普通指令实际弹道命中、边框/塔身遮挡、击毁/重建/五分钟限制、配置读写和切换后的统计/内参保留。图形检查通过实际控件验证隐藏关系、位置编辑、红蓝灯效、击毁后熄灭和重建恢复；截图位于被忽略的`.tools/verification/outpost2026/`。

以下两次历史闭环使用了误选的基地标识，不能作为正确前哨站图案的识别验收；数值仅保留为诊断记录。

NUC首轮原生OpenGL与原有CPU自瞄MPC闭环：25秒记录1067幅真实相机帧，实际发射175发、14次有效命中、扣血280；控制指令模式均为1，仿真拒绝数0。173次已结算事件包括塔身碰撞65、边框22、进入有效区域19（其中5次法向速度不足被拒绝）、越界清除67。尚有在飞弹丸，因此不能把175发直接当作已结算数计算命中率。结果证明原模型能产生实际控制、发射和命中，但当前命中率偏低，不能宣称已调好前哨站；原因仍需结合识别、跟踪、预测和物理日志单独定位。本轮没有为了提高命中率改变2026布局或放宽算法/受击规则。

修正图案前的代码在NUC再次验证：前哨站核心88项、图形34项通过；25秒旋转场景记录1040帧、发射115发、有效命中1次、伤害20，113发已结算、2发在飞。相同相机和算法配置、通过正常基地展开事件停转的对照场景记录1166帧，但没有形成有效控制或发射。因此尚未通过原模型稳定识别/跟踪/击打前哨站的验收，不能由少量命中推出识别可靠；具体卡在检测、分类、跟踪还是规划仍需诊断。验证均在独立副本和通道运行，未覆盖NUC日常工作空间。

### 修正前哨站标识后的复测

将误用的基地标识换成官方带圆点细塔图案，增加贴图特征检查；NUC核心88项、图形40项通过。使用相同相机参数和原有CPU自瞄MPC配置，旋转靶25秒记录1069帧、实际发射218发，已结算216发，其中11次有效命中、87次阻挡、118次越界，造成240点伤害，2发仍在飞；接收1662条有效指令、拒绝0。停转对照25秒记录1163帧，仍未形成有效控制或发射。仅可确认旋转场景中原模型产生了控制、发射和有效命中，尚不能宣称稳定识别和击打通过。未修改算法、阈值、控制参数或受击规则。
